# Routing algorithms — complexity analysis & benchmarks (Phase 3)

Notation: `V` = nodes, `E` = edges, `K` = size of the Pareto front, `B` =
number of blockage events in a dynamic episode.

| # | Algorithm | Time complexity | Space | Notes |
|---|-----------|-----------------|-------|-------|
| 1 | Dijkstra (binary heap) | `O((V + E) log V)` | `O(V)` | baseline; nonnegative costs guaranteed by `costs.py`. |
| 2 | A* (admissible, consistent h) | `O((V + E) log V)` worst case; far fewer expansions in practice | `O(V)` | heuristic = straight-line distance ÷ global max speed (lower bound on remaining time). |
| 3 | Static-risk Dijkstra | `O((V + E) log V)` | `O(V)` | identical to #1 with `cost = time + λ·static_risk`. |
| 4 | Uncertainty-aware Dijkstra (and UCB) | `O((V + E) log V)` | `O(V)` | `cost = time + β·(−log(1−p))`. Additive survival penalty ⇒ plain SP. |
| 5 | Chance-constrained | `O(I · (V + E) log V)`, `I ≈ 40` bisection steps | `O(V)` | Lagrangian relaxation + bisection on μ. |
| 6 | Multi-objective Pareto (label-setting) | worst case exponential; with ε-dominance bounded to `O(C · (V + E) log(·))` where `C` = ε-cells | `O(V · L)`, `L` labels/node | NP-hard in general; ε-dominance + target bounding make it tractable (documented accuracy tradeoff). |
| 7 | D* Lite (per repair) | `O(k log k)` for `k` affected vertices; `≪` full recompute when changes are local | `O(V)` | incremental; builds once, repairs per blockage. |
| 7 | Full recompute (baseline) | `O(B · (V + E) log V)` | `O(V)` | re-runs Dijkstra each blockage. |
| 8 | Min-cost max-flow (SSP) | `O(F · (V + E))` with SPFA, `F` = total flow | `O(V + E)` | successive-shortest-path; capacities respected by construction. |
| 8 | MSA congestion assignment | `O(N_iter · MCMF)` | `O(E)` | Method of Successive Averages; step `1/k`, parameter-free, convergent. |
| 9 | Accessibility Dijkstra | `O((V + E) log V)` | `O(V)` | profile forbids edges (∞ cost) + slope/lit penalties. |

## Admissibility of the A* heuristic (proof sketch)

For `DISTANCE` mode, `h(n) = haversine(n, goal)`. The great-circle distance is
a lower bound on any path's road distance (roads are at least as long as the
straight line on the sphere), so `h` never overestimates ⇒ **admissible**. It
also satisfies the triangle inequality on the sphere ⇒ **consistent**.

For `TIME`/risk/uncertainty modes, `h(n) = haversine(n, goal) / v_max` where
`v_max` is the maximum edge speed in the graph. Any remaining path takes at
least `distance / v_max` seconds, and all risk/uncertainty penalties are
nonnegative, so `h` is a lower bound on remaining cost ⇒ **admissible**.
Property test `test_astar_heuristic_admissible_never_overestimates` checks
`cost_A* ≥ cost_Dijkstra` across many seeded pairs (admissibility ⇒ optimality).

## Measured latency (SYNTHETIC graphs, sandbox desktop)

From `results/bench_routing_SYNTHETIC.csv` (median of repeated runs, single
source→nearest-shelter query). These are **desktop/sandbox** numbers; on-device
(mid-range Android) latency for **H5** is a separate measurement and is marked
**UNVERIFIED** until collected via the PWA harness (see `docs/REPRODUCE.md`).

Representative figures (nx=30, 900 nodes / 3274 edges):
Dijkstra ≈ 0.17 ms · A* ≈ 0.15 ms · uncertainty ≈ 0.27 ms ·
chance-constrained ≈ 0.39 ms · Pareto (ε-dom) ≈ 1.3 ms · D* Lite build ≈ 4.7 ms.

**D* Lite vs full recompute:** on repeated mid-route blockages, D* Lite repairs
only the affected subtree; see `routing.benchmark.dstar_vs_recompute` for the
per-event comparison (regenerated by `make experiments`).

> Known limitation: multi-objective Pareto remains the most expensive method and
> can exceed a few hundred ms on hard long-distance pairs even with ε-dominance.
> For on-device use we recommend the chance-constrained method (bounded, fast)
> and reserve full Pareto for the desktop route-comparison view. Recorded in
> `docs/LIMITATIONS.md`.
